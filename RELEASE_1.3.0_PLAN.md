# RELEASE 1.3.0 PLAN — correctness-hardening + testing program

This plan covers the post-1.2.x work: closing the last user-facing correctness
gap that keeps tlaplusplus a "cross-check accelerator" rather than a trusted
oracle (terminal-state deadlock detection), plus a testing program that widens
our confidence in the native frontend against TLC.

The framing motivating this cycle: a downstream user deliberately has NOT
switched their trusted verdict matrix onto tlaplusplus. The Java oracle (TLC)
cleanly delivers all three verdicts (safety, liveness, deadlock); tlaplusplus is
a post-15/15 cross-check accelerator. One concrete blocker they named is that
tlaplusplus "exposes no -deadlock control, a real risk for the quiescent Fix
cells." Roadmap #1 below closes that gap directly.

## Roadmap

### #1 — Terminal-state deadlock detection (this PR)

**Problem.** TLC's default deadlock check reports any reachable state with no
successor under `Next` (no action enabled) as a deadlock, unless disabled with
`-deadlock` / `CHECK_DEADLOCK FALSE`. tlaplusplus had **no** terminal-deadlock
detection whatsoever. The `--allow-deadlock` flag and `CHECK_DEADLOCK FALSE`
only gated the eval-error branch (whether a failing action eval panics or is
swallowed as a disabled branch); a genuinely quiescent state was silently
accepted as an exploration leaf. So tlaplusplus could not detect a deadlock at
all — it always behaved as if `-deadlock` were passed. This is the inverse of
what a user needs from a deadlock oracle.

**Design.**
- `Model::deadlock_check_enabled(&self) -> bool`, default `false`. Synthetic /
  stress models (CounterGrid, etc.) legitimately reach terminal states and must
  not be flagged, so the trait opts out by default.
- `TlaModel` overrides it to `!self.allow_deadlock`, so TLA+ models report
  deadlock unless the user disabled the check (CLI `--allow-deadlock`, or
  `CHECK_DEADLOCK FALSE` in the cfg, both of which set `allow_deadlock`).
- The worker checks the **raw** successor count — the number of successors
  generated by `next_states`, *before* the state/action-constraint `retain`
  filter — so the trigger is "no action enabled", matching TLC's next-state
  relation. A state pruned to zero successors purely by a `CONSTRAINT` /
  `ACTION_CONSTRAINT` is a constraint boundary, not a deadlock. (See the open
  question below — we validate this choice against TLC.)
- Reported through the existing violation channel with a new
  `PropertyType::Deadlock`, reusing the invariant path's parent-chain trace
  reconstruction, and honouring `--stop-on-violation` / `--max-violations`.
- Ordering: a reached `Assert(FALSE)` (drained earlier in the loop) takes
  priority — that path `continue`s before the deadlock check.

**Open question (validate against TLC, the oracle).** Does TLC count a state
whose only enabled actions lead to constraint-excluded successors as a deadlock?
TLC evaluates the next-state relation independently of state constraints for the
deadlock check, so a state with enabled actions is not a deadlock even if every
successor is later pruned. Our "raw count before filter" choice matches that
reading. The differential gate (below) with deadlock checking *enabled* on both
sides is how we confirm it on real specs.

**Tests.** `tests/deadlock_detection.rs` — report-on, suppressed-by-allow,
self-loop-is-not-deadlock, init-state-deadlock. Plus the differential gate with
deadlock ON (testing #1).

## Testing program

Ranked by leverage. All builds/tests run on spot instances, never locally.

### #1 — Deadlock parity (this PR)
Rust integration tests (`tests/deadlock_detection.rs`) + a differential-gate
lane that runs both engines with deadlock checking **enabled** (the existing
`diff_tlc.sh` always passed `--allow-deadlock`/`-deadlock`, so deadlock was
never differentially tested). Add deadlocking specs to the diff corpus.

### #2 — Widen the differential gate
Grow `corpus/diff_test/list.tsv` beyond the current 13/23 curated specs toward
the broader `tlaplus/Examples` set, comparing **full reachable sets** (never
stop-at-violation counts — see the ACP lesson). Track distinct-state and verdict
agreement per spec.

### #3 — Metamorphic relations
Properties that must hold without a TLC oracle:
- Adding a redundant conjunct to an invariant that is already implied must not
  change the verdict or state count.
- Symmetry reduction on/off must agree on verdict (already partially covered).
- `--por` on/off must agree on safety verdict.
- Reordering `Next` disjuncts must not change the reachable set.

### #4 — Loom concurrency tests
Model-check the fingerprint-store CAS + seqlock resize and the work-stealing
termination handshake under `loom` for a small bounded thread/op count. Targets
the exact code Verus proves, from the runtime side.

### #5 — Fuzz cfg parser + action splitter
New fuzz targets: `.cfg` parser (`src/tla/cfg.rs`) and the action-body disjunct
splitter (`split_action_body_disjuncts`), which has been a repeated source of
bugs (#187/#188). Feed malformed and adversarial nesting.

### #6 — Cluster differential routine
Extend the cross-machine DFS-cluster real-TCP test to a differential: N-node
partitioned run vs single-node baseline must agree on distinct-state totals
(already validated ad hoc at N=2/3/4; make it a routine gate).
